## 1. 已定决策（D-01 ~ D-06：项目定位与载体）

| 编号 | 决策 | 理由 | 影响 |
| --- | --- | --- | --- |
| D-01 | 定位为"AI 应用工程 + 平台后端双线"，硬点优先、LLM 做增强 | 面试官能追的是工程硬点，不是"用了大模型"这件事本身 | 数值全部确定性计算，LLM 只出草案 |
| D-02 | 载体为 `D:\项目zz` 独立仓库，复制作品一脚手架、不复用业务代码 | 作品一已冻结，两个作品要能分别讲、互不牵连 | 目录结构与工程规范同源，减少学习成本 |
| D-03 | 文档先行，再分阶段实现到可演示 | 作品一的经验：先定稿再动手，返工最少 | P1 只产出文档，不写业务代码 |
| D-04 | 周期 10–12 天、七个阶段、每阶段一个里程碑 | 两个场景 + 三条链路 + 五页面 + 三格式导出，7 天只能每样做一半 | 若时间压缩，优先砍前端页面数 |
| D-05 | 云端 DeepSeek 主力 + 本地 `bge-m3` | 实测账号可用 `deepseek-flash`/`deepseek-v4-pro`，无视觉模型 | 不引入本地大模型，避免 8GB 显存与 Blackwell 轮子的坑 |
| D-06 | 架构不依赖 Docker，沙箱用受限子进程 | 实测 Docker 守护进程常不启动、历史有镜像拉取失败 | 沙箱隔离等级需如实声明残余风险 |

| D-11 | 数据全合成 + 真值预埋 + 独立核算 | 真实数据无法获取，但合成数据天然带 ground truth | 期望值禁止由被测系统自身产出 |
| D-12 | 产业调研走权威站点直连，不依赖通用搜索引擎 | 实测 DuckDuckGo 不通、Bing 查法条返回无关结果 | 逐条记录来源 URL + 抓取日期 + 用途 |

## 3. 已定决策（D-14 ~ D-21：题目与口径）

| 编号 | 决策 | 理由 | 影响 |
| --- | --- | --- | --- |
| D-14 | 主体项目选 2.1 经营归因分析系统 | 唯一能设计出"预埋真因 → 测命中率"的项目；范围可控 | 见第 5 节被推翻的 D-14a |
| D-15 | 两个场景：电商 GMV 下滑 + 快消品利润率异动 | 恰好覆盖乘法（LMDI）与加法（差额分析）两套方法论 | SaaS 续约率不进范围（比例型无干净恒等式） |
| D-16 | GMV 取支付成功口径；毛利额而非毛利率作为根指标 | 比率型指标无法做守恒分解 | 口径版本化并写入会话与报告 |
| D-17 | 只对可加或可乘结构做分解；比率型不分解 | 守恒断言是硬约束，比率结构立不住 | 指标字典保存时强制校验结构 |
| D-18 | 守恒容差 1e-9（相对误差），失败即缺陷 | 允许"差不多"就无法审计 | 抽出统一的断言函数 |
| D-19 | Shapley 降级为"按占比分摊"并声明其为启发式；砍掉杜邦分析法、桑基图 | 保留能力、去掉不必要的黑话与冗余图形 | 术语手册 T2/T3 逐条说明 |
| D-20 | 新增业务术语手册 + 每阶段业务讲解卡机制 | 使用者无行业经验，术语必须可被复述与追问 | 讲解卡是唯一不可跳过的软性出口 |
| D-21 | 合成数仓 500 万行、18 个月、四维度 | 太小谈不了性能、太大重置成本高 | 若生成/重置超时则下调到 200 万行并记录 |
