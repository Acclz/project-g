# docs 目录索引

**每份文档只有一个权威范围。** 新增内容前先看归位规则，避免文档膨胀成互相矛盾的三份说明书。

| 文档 | 权威范围 | 什么时候看 |
| --- | --- | --- |
| [`00-项目共识确认书.md`](00-项目共识确认书.md) | 设计树定稿：21 条决策、三态标记、术语分层、排期与签字 | 想知道"当初为什么定成这样"、或要核对范围是否被改过 |
| [`00-需求说明书.md`](00-需求说明书.md) | 要做什么：能力、页面、业务规则、验收标准、演示场景 | 想确认范围、验收标准、两个演示场景 |
| [`01-技术规格.md`](01-技术规格.md) | 架构 / 数据模型 / 接口 / 分词与分解算法 / 沙箱实现 / 部署 | 想知道表怎么设计、接口长什么样、沙箱怎么隔离 |
| [`02-流程与规范.md`](02-流程与规范.md) | 阶段流程 / 工程规范 / 验证档位 / 范围裁剪台账 | 每阶段开工与收尾；写代码前必读 |
| [`03-进度与质量.md`](03-进度与质量.md) | 现状评估 / 实测指标 / 评测记录 / 环境问题与规避 | 想知道做到哪了、指标多少、踩过哪些坑 |
| [`04-决策记录.md`](04-决策记录.md) | 决策与理由（含被推翻的旧决策） | 想知道某次取舍的来龙去脉 |
| [`guide/`](guide/README.md) | 代码导读 + 业务术语与口径手册 | 读代码前先读术语手册；读代码时按模块导读 |
| [`submission/`](submission) | 交付材料：面试问答册、截图、演示脚本说明 | 准备面试 / 整理课程提交包 |
| [`archive/`](archive) | 历史文档（调研稿等） | 仅作追溯，不作依据 |

## 归位规则

| 内容类型 | 写进哪份 |
| --- | --- |
| 需求、验收标准、演示场景、业务规则 | `00-需求说明书` |
| 接口、表结构、算法细节、沙箱与部署 | `01-技术规格` |
| 阶段目标、工程规范、验证档位、被砍掉的验收项 | `02-流程与规范` |
| 进度、实测数据、报错与环境结论 | `03-进度与质量` |
| 决策与理由（含推翻旧决策） | `04-决策记录`，定稿版摘要见 `00-项目共识确认书` |
| 某模块怎么读、为什么这么写、术语与口径 | `guide/` |
| 面试与交付材料 | `submission/` |

**不要新建第 5 份顶层文档。** 放不进任何一格时，先改这份索引，再动手。

## 阅读顺序建议

第一次接触：`00-项目共识确认书` → `00-需求说明书` → `guide/03-业务术语与口径手册` → `02-流程与规范` → `03-进度与质量` → `01-技术规格` → `04-决策记录` → `guide/`
